# Phase 9: The Generative Evolution Loop (Detailed Implementation Plan)

## 1. Objective and Scope
Phase 9 ties everything together into the final Generative Evolution Loop. We will finalize the LangGraph execution, implement chemical validation via GraphRAG *before* prediction, establish the Fitness Function, and wrap the entire process inside the asynchronous Celery worker to communicate with the frontend.

---

## 2. Chemical Validation (The Missing Step)

Before sending materials to the LLM Predictor (Phase 8), we must weed out chemically impossible mutations created by the GA (Phase 7).

### 2.1 GraphRAG Validation Filter
- Modify the `mutator_node` or create a new `validator_node`.
- For every child generated by the GA, ask the GraphRAG Engine: *"Is {child_composition} a structurally stable battery material, or does it violate fundamental valence rules?"*
- Use a fast, cheap LLM call (e.g., Haiku) to evaluate the GraphRAG context and return a boolean `is_valid`.
- Discard invalid materials and force the GA to generate replacements until the population is full of valid materials.

---

## 3. The Fitness Scoring Function

Once materials have predicted properties, we must score them to determine which survive to the next generation.

### 3.1 Mathematical Scoring (`app/services/ga/fitness.py`)
Write a deterministic math function based on the user's initial requirements (from Phase 6).
- Example Formula: `Fitness = (Capacity * Voltage * Cycle_Life) / Cost`.
- Add penalties for violating user constraints (e.g., if the user specified "Capacity > 200", and the prediction is 180, slash the fitness score by 50%).
- Inside the LangGraph flow, immediately after the `predictor_node`, loop through the population, calculate this score, and sort the population from highest to lowest fitness.
- Update the `best_candidates` array in the `ResearchState` with the absolute best materials found so far across all generations.

---

## 4. Celery Worker Integration (`worker/tasks.py`)

The LangGraph orchestration must run asynchronously.

### 4.1 Invoking the Graph
Create the Celery task that takes the user's prompt.
```python
from app.agents.workflow import app_graph
from app.core.celery_app import celery_app

@celery_app.task(bind=True, name="run_discovery_loop")
def run_discovery_loop(self, user_prompt: str, task_id: str):
    # Initialize empty state
    initial_state = {"user_prompt": user_prompt, "task_id": task_id, "logs": []}
    
    # Run the graph stream to get live updates
    for event in app_graph.stream(initial_state):
        for node_name, state_update in event.items():
            # Update Redis with live generation count
            if node_name == "mutator":
                gen = state_update.get("current_generation")
                self.update_state(state='PROGRESS', meta={'message': f"Mutating Generation {gen}..."})
                
    final_state = app_graph.get_state().values
    return final_state["best_candidates"]
```

### 4.2 FastAPI Status Polling (`app/api/v1/endpoints/research.py`)
- Implement `GET /api/v1/research/status/{task_id}`.
- Use Celery's `AsyncResult(task_id)` to read the state and meta information from Redis.
- Return the live progress message to the React frontend.
