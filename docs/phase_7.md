# Phase 7: The Generative Evolution Loop (Detailed Implementation Plan)

## 1. Objective and Scope
Phase 7 ties everything together into the final Generative Evolution Loop. We will implement critical chemical validation via GraphRAG *before* prediction, establish the Fitness Scoring Function to rank the materials, and wrap the entire LangGraph process inside the asynchronous Celery worker so it can run for several minutes while communicating live progress to the frontend.

---

## 2. Chemical Validation (The Missing Filter)

Before sending 20 materials to the LLM Predictor (Phase 6), we must weed out chemically impossible mutations created by the GA (Phase 5). This saves API costs and prevents the LLM from hallucinating properties for impossible materials.

### 2.1 GraphRAG Validation Filter
- Modify the `mutator_node`. For every child generated by the GA, we must validate it.
- Ask the GraphRAG Engine: *"Is {child_composition} a structurally stable battery material, or does it violate fundamental valence rules? Check the structural rules provided."*
- Use a fast, cheap LLM call (e.g., GPT-4o-mini) to evaluate the GraphRAG context and return a strict JSON boolean: `{"is_valid": true}`.
- If `is_valid == false`, discard the material and force the GA to generate a replacement child until the population of 20 is full of exclusively valid materials.

---

## 3. The Fitness Scoring Function

Once materials have predicted properties (Phase 6), we must score them to determine which survive to the next generation.

### 3.1 Mathematical Scoring (`app/services/ga/fitness.py`)
Write a highly deterministic math function based on the user's initial requirements extracted by the Planner Agent (Phase 4).
- **Base Score Formula:** Combine normalized properties into a single heuristic. 
  - Example: `Base Score = (Capacity * Voltage * Cycle_Life) / Cost`.
- **Constraint Penalties:** 
  - Read the `target_properties` from the `ResearchState`.
  - If the user specified `capacity_gt: 250`, and the prediction is `180`, apply a massive penalty (e.g., multiply the final score by `0.2`).
  - If the user specified `cost_lt: 50`, and the prediction is `75`, apply another penalty.
- Inside the LangGraph flow, immediately after the `predictor_node`, loop through the annotated population, calculate this score, and append `"fitness_score": X` to each material.
- Sort the population from highest to lowest fitness.
- Update the `best_candidates` array in the `ResearchState`. Compare the top materials of the current generation against the all-time `best_candidates` list. Keep the absolute top 5 materials found so far across all generations.

## 4. Celery Worker Integration (`worker/tasks.py`)

The LangGraph orchestration will take roughly 3-5 minutes to complete 20 generations. It must run asynchronously to prevent HTTP timeouts.

### 4.1 Invoking the Graph Stream
Create the Celery task that takes the user's prompt and executes the graph.
```python
import asyncio
from app.agents.workflow import app_graph
from app.core.celery_app import celery_app

@celery_app.task(bind=True, name="run_discovery_loop")
def run_discovery_loop(self, user_prompt: str, task_id: str):
    # Initialize empty state
    initial_state = {
        "user_prompt": user_prompt, 
        "task_id": task_id, 
        "logs": [],
        "best_candidates": []
    }
    
    # Run the graph stream synchronously inside the Celery worker
    # We use stream() to get live updates every time a node finishes
    for event in app_graph.stream(initial_state):
        for node_name, state_update in event.items():
            
            # Update Redis with live generation count and best score
            if node_name == "predictor":
                gen = state_update.get("current_generation")
                best_score = state_update.get("best_candidates")[0].get("fitness_score", 0)
                
                self.update_state(
                    state='PROGRESS', 
                    meta={
                        'message': f"Completed Generation {gen}...",
                        'generation': gen,
                        'best_score': round(best_score, 2)
                    }
                )
                
    # Once the loop ends, grab the final state
    final_state = app_graph.get_state().values
    return {"status": "success", "results": final_state["best_candidates"]}
```

### 4.2 FastAPI Status Polling (`app/api/v1/endpoints/research.py`)
- Implement the polling endpoint: `GET /api/v1/research/status/{task_id}`.
- Use Celery's `AsyncResult(task_id)` to read the state and meta information from Redis.
- Return the live progress message, generation count, and current best score to the React frontend.

## 5. Execution and Verification Checklist

1. **Validation Test:** Force the GA to mutate a completely nonsensical material (e.g., `Li100Ni0O2`). Verify that the GraphRAG Validation Filter correctly identifies it as structurally impossible and discards it.
2. **Fitness Function Test:** Write unit tests for the fitness scoring. Provide dummy materials where one meets all user constraints and one violates the capacity constraint. Verify the violator's score is heavily penalized.
3. **End-to-End Trigger:** Submit a research task via the FastAPI `POST /api/v1/research/start` endpoint using Postman.
4. **Log Monitoring:** Monitor the Celery worker terminal logs; verify that it successfully iterates through multiple generations without crashing or throwing async loop errors.
5. **Polling Verification:** Poll the `GET status` endpoint rapidly. Verify it returns live updates (e.g., "Completed Generation 2... Best Score: 450.2") which proves Redis is successfully tracking the LangGraph state mid-execution.
